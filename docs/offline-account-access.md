# Offline access tied to the designated administrator account

Problem: the existing singleton enrollment checks both owner and installation UUID. The Android UUID is generated once in the app's private database; it is not hardware identity. A distinct application ID or clearing/reinstalling data can therefore hit a stale installation gate on the same physical phone. A normal same-package/same-certificate update should retain that UUID. The user's latest screenshot shows Android 2.6 but does not show the access dialog, so its precise current denial reason has not been confirmed.

Requested behavior: remove the single-installation restriction while keeping offline access with the already designated administrator account. All offline endpoints remain authenticated and Administrator-only. Access, enrollment and device validation now compare the designated owner, not the first installation UUID. Empty UUIDs remain invalid. An existing owner cannot be replaced by a different account through enrollment.

Compatibility: existing APK 2.6 can use the change. No new Android package, database migration, data deletion or enrollment reset is needed. Keep the original singleton row, first installation ID and enrollment timestamp for audit compatibility. Receipts still record each operation's actual installation UUID. Receipt identity, per-installation dependencies, stock/workspace/bowl concurrency and exactly-once behavior remain enforced. Conflicting edits stop and preserve local work. Removing this gate is not a claim that simultaneous offline editing of the same item will automatically merge.

Validation: .NET 10 SDK build of WorkspaceSmoke/API/Panel succeeded (20 pre-existing warnings, no errors). Run `dotnet tests/WorkspaceSmoke/bin/Debug/net10.0/WorkspaceSmoke.dll --offline-only`: complete offline production smoke passed, including new same-owner replacement-installation access and snapshot addressing, retained enrollment/time, cross-installation receipt identity rejection, stale-version rejection and dependency isolation. Existing tune-to-QC, stock, photos, accounting, payroll-related event handling, warranty retry, orders and PostgreSQL migration-model checks passed. Tests used isolated in-memory SQLite and test users, never production data.

Release scope: API service change only; domain edit is explanatory comments. Panel/Android changes are not part of this branch. At preparation time origin/master and origin/deploy-api have identical versions of the affected service/entity. Production deployment and handset behavior have not been verified. No GitHub push, PR, merge, production deployment or database mutation was performed for this change.
