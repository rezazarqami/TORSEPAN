# Torsepan Offline 2.11.1 — name and page consistency

Prepared after the 2.11.0 candidate; no push or live deployment performed.

The Android launcher/application label and bundled document title are now `Torsepan Offline`. The offline menu footer uses the same name. Package ID remains `ir.torsepan.mobile.offline`, versionCode increases from 17 to 18 and versionName is `2.11.1-offline`. Signing verification matched the previously delivered 2.11.0 APK, so it is an in-place update. No local database, encryption-key or pending-operation changes are included.

The page audit confirms that ordinary business pages use the shared online Panel Razor components, forms, models and styles. Dedicated offline copies remain for Dashboard, Backups, Reports, PayrollTable, NewHandpan, the photo gallery and Sidebar. Dashboard differences refresh local data; PayrollTable/Reports print locally; Backups adds phone backup; NewHandpan uses the correct local bowl enum; the gallery uses local event/upload handling. Offline activation, the sync strip, queue, cached photos and local data handling are intentionally specific to this application. Data reflects the last snapshot plus locally queued operations rather than live online data.

Two missing `navy-management-page` wrappers on Reports and Backups were restored to match the online layout/theme. The existing legacy-stock page was already shared and locally supported, but its menu link was missing; `ثبت سازهای قدیمی` is now accessible in the administrator menu. The online app-download option remains unnecessary inside the local interface; returning to the web retains its dedicated action.

Validation: release WebAssembly build, Android release assembly and release lint passed. The verified APK has the requested application label, the same signer, increasing version and a byte-identical complete offline panel bundle. All 23 selected shared routes opened with external requests blocked, and the actual production/work-plan forms persisted across restart. Physical-device installation is not claimed. The API publication/initial-sync prerequisites documented for 2.11.0 still apply.
